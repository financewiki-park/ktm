# 0.1.13 — Telegram 명령을 Kindle에서 실제 실행

## 사용 목적과 흐름

사용자가 Telegram 봇에게 설치 명령 등을 보낸다. Kindle에서 KTM을 열고 5번을 선택하면
최근 명령을 받아 전체를 표시한다. `r` + Enter를 누르면 `/bin/sh`가 실행한다.
명령 출력, 오류, 설치 중 질문은 같은 공식 KTerm 창에서 표시되고 입력할 수 있다.
종료 코드를 보여준 뒤 사용자 Enter까지 결과 화면을 유지한다.

아래 두 줄을 한 메시지로 보내면 변수 지정과 설치가 같은 셸에서 진행된다.

```sh
KPM=/var/local/kmc/bin/kpm
"$KPM" install ktm
```

Markdown 울타리나 설명문을 포함하지 않은 명령 본문을 보낸다.
앱 업데이트 시에도 토큰과 페어링, 수신 원문은 유지된다.

## 구조

`Telegram → current.txt 한 건 → 5번 → 검토용 사본 → 사용자 실행 확인 → /bin/sh → KTerm 결과 표시`

- 받은 명령을 C helper가 하나의 임시 파일로 고정해 검토와 실행에 같은 내용을 사용한다.
  확인 중 새 Telegram 메시지가 도착해도 실행 대상이 바뀌지 않는다.
- 문법을 먼저 `/bin/sh -n`으로 검사한다. 확인 전에는 명령을 실행하지 않는다.
- 명령은 문자열을 shell 인자에 끼워 넣지 않고 파일로 전달한다.
- stdin/stdout/stderr는 KTerm에 연결되므로 설치 질문에 응답할 수 있다.
- 작업 디렉터리는 `/mnt/us`. 한 메시지 안의 변수와 `cd`는 후속 줄에 적용된다.
  메시지 간에는 셸 상태를 유지하지 않는다.
- 5번은 긴 명령, 여러 줄, 파이프, heredoc을 지원한다. 512바이트 제한은 8번 편집에만 적용된다.
- 원문은 보존하고 실행 사본만 작업 종료 시 제거한다. 수신만으로 실행하지 않는다.
- Enter만 누르면 취소한다. 수신 원문에 NUL/ESC 등 제어문자가 있으면 실행을 거부한다.

## 검증

실제 PTY에서 설치 명령 형태의 두 줄 스크립트, 한글·512바이트 초과·heredoc·파이프,
사용자 확인 전 미실행, 취소, 설치 질문 응답, 검토 중 메시지 변경, 문법 오류,
종료 코드, CRLF 및 원문 보존을 검사한다. ARM 빌드도 QEMU에서 같은 검사를 수행한다.
GUI 진입에는 0.1.12의 공식 KTerm 실행 경로를 그대로 사용한다.
Kindle 실기기 화면 검증은 여전히 별도 확인이 필요하다.
